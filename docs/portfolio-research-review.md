## 设计决定建议

1. 叙事区建立“后训练 → Agent 实践 → 成果 → 生活”的节奏；资料入口使用大肖像、直接可读的定位与事实，随后再提供详录。
2. 羽毛球章有专属空间和运动事件，保留羽片、羽轴、绑线、软木球头及开放线床的真实三维结构。独立场景应与纸白、墨色、朱砂体系一致。
3. 交互只围绕本人兴趣展开：慢旋、拖动观察和一次明确的击球足够。不要添加分数、排名、速度榜或其他无关玩法。
4. 生活内容使用已有的具体描述。正文承担信息，三维文字只作为场景标记；不得让访客阅读透视缩小后的纹理来理解经历。
5. 不因模型更复杂就视为视觉通过。留白、主次、姿态、接触关系和镜头节奏都须通过实际画面判断。

### 第 1 轮 — FAIL

- 交付状态：实现者已添加羽球/球拍场景、`rallyPose` 运动轨迹和直接可见的个人资料，正在初检。
- 代码审查：已读 `App.jsx`、`Film.jsx`、`Dossier.jsx`、新增 CSS、`BadmintonScene.jsx`、`BadmintonModel.js` 与 `badminton.test.mjs`。结构查询先使用 codebase-memory；索引未包含新模块，因此以当前文件为准。
  - 真实几何包括 16 片曲面羽片、羽轴、羽枝、绑线、Lathe 球头、管状球拍框和独立线床。模型材质与几何有释放路径。
  - `rallyPose(.34)` 将球头尖端置于拍面中心，出球方向与接触时拍面法向一致；单测核对接触点。这能证明几何约束，不能证明整段运动观看自然。
  - 渲染循环在离屏和后台退出；鼠标拖动与实际按钮入口存在，触摸交互交给按钮并保留纵向滚动。
  - 已提醒实现者：新增正文存在 `font-weight:600`，与本轮“全部加粗”及 700 基线不一致。
  - 待实测风险：1.7 秒运动尚未结束时可再次触发并重置 `shotStart`，须确认不会反复跳姿态或产生“球拍挥空”的观感。
- Chrome 视觉与交互证据：交接后使用独立 Chrome 标签页 `1859663468`，检查 `http://127.0.0.1:4173/`。默认桌面 CSS 视口 1470 × 775、DPR 2；响应式视口 390 × 844 和 320 × 568；Chrome 原生菜单快捷键放大到 200%，CSS 视口实测 735 × 387、DPR 4。未使用应用内浏览器作为视觉证据。
- **P2 / FAIL：减少动态效果的静止首页未保持粗体。** 在 Chrome DevTools 命令菜单选择 `Emulate CSS prefers-reduced-motion: reduce`，页面正确改为静止三维入口，但 `.static-intro > h2` 的 computed 字重为 500，`span` 和 `p` 为 400。常规首页与新增个人页已为 700，静止路径却违背用户要求。截图：`outputs/visual-review/subagent-reduced-motion.png`。
- 其他实际通过项：
  - 桌面个人入口的肖像、姓名、职业和事实有清楚主次。研究与实习直接可读，不再藏在“关于与生活”tab 中。
  - 390 和 320 下，姓名/职业在左、肖像在右，研究、实习、教育全宽排列。320 下职业保持两行，实习日期的“至今”自然换行；无横溢。正文 16–17px，未通过整体缩放塞入。
  - 生活章具有独立构图：纸白背景、清晰羽片、开放线床与淡球场线。球拍、羽球、文字和按钮没有遮挡。运动在实际画面中可见蓄势、球头接近拍面、接触、离拍向右飞出和复位，而非只依赖数学测试判断。
  - 鼠标拖动可改变羽球姿态；按钮点击与回车可触发击球。通过实际 Chrome 窗口 Shift+Tab 导航至挥拍按钮，再 Return 触发，焦点环可见，章节不改变。周期内重复触发的重置风险由实现者增加 guard 后消除。
  - 在 390 宽场景区域滚动可继续进入个人资料，未被画布拦截。200% 下生活章及资料入口正常重排，没有横向滚动。
  - 回归 OPD + RL 主体、成果证书、实习文案及古厝空间。分段滚动实际观察到从外部门楼推进到院内书案，真实透视与遮挡仍成立；院内 Agent / OPD + RL / Skills / Bad Case 物件清楚可见。
  - 减少动态效果确实使 `#story` 消失、保留 `.static-intro` 和一个建筑 canvas，个人事实与兴趣仍在 DOM / 可访问性树中；未渲染羽球动画。
- 排除的工具现象：Playwright `locator.press('Enter')` 自动聚焦绝对定位按钮时曾让 scrollY 从生活 82% 回退到 78%，造成短暂叠影。使用点击后回车、逐次 Tab 导航与 Chrome 原生键盘均未复现，因此不计为网站缺陷，也不将该方式作为键盘验收证据。

### 第 2 轮 — PASS

- 实现者添加 `.static-intro > :is(span,h1,h2,p) { font-weight:700; }`，保持原有字号，重新构建。

## 测试边界

- 390 / 320 是 Chrome 响应式视口测试，不是真机。点击、键盘与页面滚动已实测；触屏手势的 `pointerType='touch'` 路径通过代码审查确认保留纵向滚动，本轮未做触摸硬件测试。
- 离屏/后台停止 RAF 与几何释放通过当前代码审查确认，没有宣称测过 GPU 占用或低端设备帧率。
- 浏览器日志中观察到的是 Zotero 扩展连接错误与 Remotion 提示，没有将扩展错误归为本次网站缺陷。
- 本轮没有重测未改动的所有外链、邮箱/电话发送或证书弹窗完整流程；没有执行实际发送行为。
- 构建与模型/相机单测由实现者运行并报告通过，视觉 PASS 来自上述独立 Chrome 观察。

后续每轮保留 FAIL 的具体依据、对应修复、复验结果与最终 PASS 范围，不覆盖早先失败记录。

## 2026-10-25 新要求：滚动与摄影式空间 — 第 3 轮 PASS

用户明确否定上一轮方向，要求挥拍随上下滚动而非点击，模型进一步精修，文字参与前景/后景与突近镜头。本文件上方的 PASS 是旧交互版本的历史验收，**不代表这轮要求通过**。

新增专项研究见 [motion-sites-study.md](./motion-sites-study.md)：已在 Chrome 查看 MotionSites.ai 的 Sky Cookie、Feathers Atlas、Michelle 3D portfolio 三个官方案例演示，逐段记录文字位置、尺度、遮挡、近远景与节奏。视频预览与可操控原站严格区分。验收将以新文档最后一节为准，重点检查滚动停留/反向、拍面接触、实物近景和文字空间变化。
