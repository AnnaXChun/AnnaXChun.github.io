# 全场红枫、雨后倒影与渲染预算

2026-10-25。用户已认可精细羽毛球章节，本轮保留其构图与动作。新要求是把红枫从庭院延伸到整个画面，形成枝叶探出墙外、经过镜头的感觉；进入羽毛球前逐步收回，并处理滚动卡顿与内存。

## 画面与动作

- 庭院左侧保留原枝干与根部，树冠改为五裂、锯齿、弯曲红枫叶；右侧保留疏绿层次。
- 全屏前景枫枝与 24 片落叶共用庭院 renderer，前景有独立真实三维相机，无额外 WebGL context。枝条从画面右上伸入，与后景姓名、建筑和前景正文形成距离。
- 窄屏采用更小、更高的探枝，不把桌面树冠等比压进姓名与研究巨字。落叶按投影位置在阅读区边缘柔和淡出；不逐帧读取 DOM，也不让小红叶擦过正文笔画。手机研究章的湿石倒影在标题上方消散，保留真实反射与正文留白。
- 左下章节导航按真实尺寸保留局部柔和留白，水面主体仍在门前；只在初始化/视口尺寸变化/恢复时读取导航布局，兼容 Chrome 200% 缩放，不在滚动帧读布局。成果正文与副证书题注错开，保留完整奖项与材料。
- 枝叶、落叶和细水纹依赖同一滚动帧；停滚保持、上滚恢复。前景从 frame 900 到 1080 向右上收缩，生活入口不留红叶叠在球拍上。减少动态效果保持静态。
- 门前与院内的局部湿石用一次 768×512 平面反射，带轻微水纹与不规则边缘；没有全屏 SSR。建筑仍是真实三维推拉、穿门，门洞/书案/标签坐标不变。
- 成果章建筑独立淡出，枫枝继续留在边缘；羽毛球之前才随场景收回。单个有像素上限的合成目标完成主景淡出，不额外增加 bloom 链。

## 发现与修复

| 原开销 | 本轮处理 |
| --- | --- |
| 生活章庭院 opacity=0 后仍逐帧 render，鼠标也能重绘 | 章节 active、IntersectionObserver、页面可见性一起控制；隐藏时取消 RAF |
| 穿门时 CSS width/height 随每帧变化，ResizeObserver 重配 canvas | 全屏 canvas 尺寸固定，用 Three camera viewport 重现各屏幕构图；正常滚动不调用 setSize |
| frame、pointer、resize 分别绘图 | 合并到同一个请求帧；不重复提交同一浏览器帧 |
| 静态建筑每帧重算 2048 VSM 阴影与模糊 | 静态阴影缓存；首次就绪/恢复时重新生成，细叶影使用静态姿态 |
| 全分辨率体育半浮点 4× MSAA、透射、后处理深度缓冲 | 几何目标改 2× MSAA，透射尺寸系数 .25；去掉默认 canvas 的重复 AA 与纯后处理 depth |
| 未限定大屏 Retina 像素数量 | 两个主 renderer 均限制 280 万像素，DPR 上限 1.5；DOM 文字仍用原 CSS 字号 |
| 隐藏时仍保留大幅渲染目标 | canvas、主合成/后处理、倒影缩为 1×1；庭院阴影目标释放，返回时恢复 |
| 每次跨生活边界都卸载、解析全部模型 | 首次到达后保留已解析模型，暂停绘制；返回不重复解析/烘焙环境 |
| GLB 原始字节长期缓存、Bitmap 仅 dispose GPU | 解析完成删除 raw bytes Promise；卸载时去重 close 独占 ImageBitmap |
| 庭院叶片逐片非索引合并，水墨片元约 48 次 sin hash | 2,484 片树叶改为两个实例批次；水墨使用共享 128² 纹理、两次采样，最后 owner 释放纹理 |

实例化保留叶片密度。存储顶点从 585,516 降至 406,739，几何及实例缓冲从约 14.45 MiB 降至 10.55 MiB（约 27%）。更细的五裂叶使展开后模型三角形从约 195,172 增至 221,254；不把存储节省写成减面。非叶建筑、枝干与标签逐字节回归一致。

同口径的体育颜色缓冲配置预算：2048×984、旧 DPR 1.75 / 4× MSAA / 全分辨率透射约 623.86 MiB，新 280 万像素上限 / 2× MSAA / .25 尺寸透射约 133.50 MiB，约下降 78.6%。这是已配置目标的颜色附件估算，未含深度、canvas、阴影、模型与驱动，不是 GPU 总内存实测。Three 内部透射目标仍使用 4× MSAA；.25 是宽高比例，所以其像素数为原来的 1/16。暂停时画布与显式后处理目标缩为 1×1，内部透射目标可能仍保留约 7 MiB 颜色缓存，直到下次透射绘制调整尺寸。

## 可复现的检查与边界

开发预览带 `?renderAudit=1` 时，`.minnan-scene` / `.badminton-scene` 的 `data-render-audit` 提供绘制次数、缓冲重配次数、提交耗时、资源数量；`data-render-state` 与 canvas width/height 可核对休眠。生产构建不输出该审计数据，无遥测和性能面板。

主侧 Chrome 记录：

- 优化前首屏到实习，庭院重配次数 2→7；优化后同一路线重配次数固定为 2，绘制次数 93→155，实际穿门无缓冲重配。
- 优化前生活滚动期间，隐藏庭院绘制次数 262→332；优化后庭院停在 196，canvas 1×1，生活绘制 6→7 时庭院仍为 196。
- 旧原生 2048×1040、DPR 2 的体育缓冲为 3557×1820，约 647 万像素；新原生截图采样 2360×1186，约 280 万像素。上限也有单测覆盖。二者实际窗口高度不同，不将该数字写作同条件 FPS 对比。
- 显式 2048×1040 视口模拟实际 DPR=1；仅用于验证布局/重配/休眠，不能与原生 DPR=2 的 CPU 数字直接比较。提交耗时含 GPU 排队及首次编译，不等于帧率。JS heap 随 GC 变化，不把单次读数视作总内存降幅。
- 新增水面和前景增加了一次低分辨率反射与少量批次；不是零成本。真正收益是停掉隐藏场景、免除重复阴影/重配和限制辅助目标，未删除已认可的羽枝/线床细节。
- 构建、9 项几何/接触/滚动/调度/像素预算测试及 diff-check 通过；最终 Chrome 视觉结论见 `portfolio-research-review.md`。未声称真机、低端 GPU 或弱网测试完成。
