# 椿襄个人网站 · Design taste

更新：2026-10-25。水墨是材质与气质，建筑必须保持真实三维，且有推拉、绕行、进入建筑的镜头转场。构图与镜头以实际研究的 MotionSites 案例为依据，产品摄影质感以最新 Halora 参考继续深化。用户否定点击挥拍、固定左文右图和缺少冲击力的布局；上下滚动应驱动动作，文字必须参与前景与后景。

最新补充：用户要求匹配 Halora 手部参考的光晕、清透感与真实细节，否定此前低饱和暖灰 / sage 底色。优先导入有明确许可的精细模型，不继续用程序基础几何堆叠主体。模型精细度与布光必须一起验收；单纯增加面数、改底色或加雾不等于完成。详见 [halora-lighting-study.md](./halora-lighting-study.md)。

这是个人展示页，重点是设计感、创新和真实工作。职业定位固定为 **Agent 开发、后训练算法工程师**。

1. 个人姓名与职业定位。
2. 后训练重点：OPD + RL 智能体后训练、开源 benchmark SOTA 经历。
3. 字节跳动国际商业化部门的 Agent 开发实习。
4. 竞赛与团队成果，保留大幅真实材料。
5. 生活与联系。

项目详录同样把 OPD + RL 排第一并默认展开，字节实习第二；原有 SFT / GRPO 生命科学推理项目作为独立第三项。用户确认：字节实习为 **2026.09.20 — 至今**，部门为国际商业化，涉及 Claude Code 内核接入公司内部 Agent、业务流程适配、Skill 优化与 Bad Case Studio。用户要求后训练以经历概述呈现，不需要具体 benchmark 名称与成绩。保留其确认的 SOTA 表述，不添加榜单、分数、提升比例或论文录用信息，也不反复追问。

## 视觉方向

- **删除顶部 banner 整个容器。** 不再恢复品牌导航条，也不添加阅读模式、播放完整旅程等无关功能。
- 用真实三维的闽南古厝替代蓝白建筑：燕尾脊、红砖、白石、院落、榕树；以淡墨材质、轮廓线、干湿颗粒和宣纸留白呈现。
- 用户明确不接受游戏低模感。树木使用细分枝与弯曲叶片，保留疏密和空隙；瓦垄与墙缝避免机械等距网格，光影柔和，表面笔触需要有浓淡和干湿变化，不能以均匀噪点或降低整体透明度代替水墨。
- 用户再次否定“低模加模糊滤镜”。结构精细度先于表面特效：逐片曲面瓦、层叠檐口、椽子与撑木、实体砖缝、双层窗棂、交织树干与板根；不要给墙、木、瓦统一套亮色条纹。保留清晰轮廓与近景接触阴影，纸面留白不靠整体泛白。
- 场景承载个人内容：撤掉独立流程板，院中研究书案、开发笔记本和廊下 Skills / Bad Case 卷宗架成为镜头中的实物。朱砂细线随滚动从门外进入庭院，再依次连到物件，反向滚动可回退。不另加产品控制台、聊天功能或悬浮功能按钮。
- 场景文字全部加粗至 700，扩大主标签并删除小字号代码与解释句；贴图按物件比例生成，不能挤压长标题。页面故事标题、正文、注释和章节导航同样加粗。小屏入院后调整镜头视角范围以保留书案与卷宗架，穿门的世界坐标不变。
- 冷白 `#f4f9fc`、蓝黑 `#172d3b`、冰蓝 `#d6edf7`；砖红仅作人物印章与古厝材料。页面背景、雾色、反射和光源同步调整。这个新决定覆盖旧暖纸 / sage 方案。
- 大标题以宋体类衬线字体呈现，正文用清晰的无衬线字体。姓名有独立尺寸，不套用所有章节。
- 三维画面与页面自然连接。阅读落点不压住正文；转场可以让实物越框、遮挡后景巨字，长说明在极近景主动退场。
- 镜头有明确空间路径：远景俯瞰 → 绕行与靠近 → 穿过门楼 → 庭院近景 → 抬升拉远。必须改变相机的世界坐标与朝向，产生真实透视、遮挡和景深层次；不能用二维图片缩放、平移替代。
- 参考图、素材出处和三维实现见 [minnan-art-direction.md](./minnan-art-direction.md)。这是网站视觉场景，不冒充本人的建筑项目成果。

## 技术约束

- 当前站点入口是 `pages-site/`。根目录 `app/` 是旧站，不用于当前视觉修改。
- Remotion composition 尺寸等于容器真实 CSS 视口，不回到固定 1440/720px 画布缩放。
- `MinnanModel.js` 建立实体屋顶、燕尾、门洞、回廊、墙体、石院和榕树，按材质合并批次；不使用水墨图片平面。`MinnanScene.jsx` 负责 WebGL 资源与尺寸变化，`MinnanCamera.js` 定义滚动对应的推拉、穿门与抬升路径。旧蓝白 `WorkshopModel` / `CameraRig` 不进入当前页面。
- 相机穿门时取消鼠标摇摆与响应式距离倍增，防止路径被拉出门洞；窄屏保留同一空间行程。材质和模型只初始化一次，逐帧只更新相机、朱砂线的显示范围及标记位置并绘制。
- 资料事实集中于 `src/data.js`；无 JavaScript 备用页由 `scripts/build-profile.mjs` 在构建时同步，避免职业与经历存在两套旧文案。
- `prefers-reduced-motion` 自动提供静止的同一三维建筑与完整资料，不增加模式按钮，也不换回二维画。
- 保留证书预览、Escape 关闭及焦点返回。

## 人物与生活交互

- 个人资料入口直接呈现肖像、姓名、职业、OPD + RL、字节实习与教育背景，不再藏在“关于与生活”tab。桌面采用大肖像与事实并列，手机用紧凑肖像搭配身份，核心事实优先于长简介。
- 生活章节使用独立的真实三维羽毛球与球拍：曲面羽片、羽轴、羽枝、绑线、软木球头、开放线床。用户已否定点击挥拍。用同一滚动进度驱动球拍蓄势、球头接触、加速离拍、掠过镜头及随挥；停滚定格，上滚沿原路径返回，不用独立时间计时或复位瞬移。
- 生活兴趣的文案可直接阅读，不依赖播放或操作。墨色与朱砂保留，生活章依据最新参考使用冷白到冰蓝摄影背景；其余章节同步为冷白。不添加分数、排名或游戏任务。触屏和键盘保留原生页面滚动，不再添加挥拍按钮。
- 参考 [Brittany Chiang](https://brittanychiang.com/) 的直接事实层级、[Dennis Snellenberg](https://dennissnellenberg.com/about) 的肖像与身份比例、[Paco Coursey](https://paco.me/) 的简练内容、[Josh Comeau](https://www.joshwcomeau.com/about-josh/) 将兴趣与交互相连的方式。借鉴判断原则，不复制个人文案或无关功能。
- 一手观察、具体验收标准和每轮结论见 [portfolio-research-review.md](./portfolio-research-review.md)。模型结构和接触点单测只验证几何约束，视觉质量仍以 Chrome 中的实际审查为准。

## 摄影式构图与 MotionSites 依据

- [Sky Cookie](https://motionsites.ai/3d-websites?prompt=sky-cookie)：保持主体连续，标题分字旋转退出、下一段文字从另一深度进入。本站让巨字以透视经过镜头边缘，球拍和羽球始终保持连续位移。
- [Feathers Atlas](https://motionsites.ai/3d-websites?prompt=feathers-atlas)：采用清晰材质、极近景、越框和前景遮挡。模型细节必须经得起放大；本站增加交织线床、穿线孔、螺旋握把、羽枝、绑结和软木细纹。这是模型查看器的录像，不冒称滚动案例。
- [Michelle 3D portfolio](https://motionsites.ai/3d-websites?prompt=michelle-3d-portfolio)：让巨型文字成为近处墙面，下一组信息由后方进入可读落点。不要将所有章节套同一左侧面板，也不能只把面板从左搬到右。
- 姓名/研究关键词作为后景大字，三维物件为中景，简短事实是前景。正文随章节在左下、右侧、右上等位置组织；阅读段完整、运动段让位。生活章用冷白冰蓝摄影底、蓝黑文字与青绿涂层球拍，同冷白庭院篇章形成节奏。巨字、手部、球拍与前景正文形成遮挡层次。
- 研究基于 Chrome 实际观看的官方公开演示视频，未获取付费源码，也未宣称已操控原站滚轮。逐案例观察、对应实现规则和新验收门槛见 [motion-sites-study.md](./motion-sites-study.md)。

## 参考调研的可复用判断

- **产品摄影质感**：宽侧上主光塑形，窄反射带勾勒拍框，暗侧保留体积；环境反射、投影与材料粗糙度一起校准，不靠高强环境光把所有表面照平。水墨色料只改变材质本色，不能再次压平真实受光和檐下阴影。
- **材料真实性**：羽球底座是暖白皮革包覆软木；羽毛、皮革、碳纤维涂层、编织线床与握把有各自光照响应。拍框反射应随滚动姿态自然移动，停滚时光影同时停住。近景中检查羽枝、孔眼、薄边与缠带，不能只看远景轮廓。
- **借鉴参考的范围**：Halora 的明亮背景、方向性日光、反射渐变、克制投影和满屏摄影构图可转译；其照片 / 视频、“场景不在代码中绘制”、商城导航和指标卡不成为本站要求。继续真实三维、滚动挥拍、穿门镜头与个人真实内容。

- [React Bits](https://reactbits.dev/)、[Aceternity Hero Parallax](https://ui.aceternity.com/components/hero-parallax)：借鉴空间层次与节奏，不能因为组件可用就堆叠功能。
- [Uiverse](https://uiverse.io/)、[Anime.js](https://animejs.com/documentation/)、[MotionSites](https://motionsites.ai/)：局部视觉与动效参考，不将营销数量或商业页面作为规范。
- [IBM Carbon Typography](https://carbondesignsystem.com/elements/typography/type-sets/)：expressive 的 16px 正文与流式标题作为可读性参考。
- [W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：用真实缩放、重排检查内容，不能靠压缩字号塞满画面。

## 开放模型与清透光影（最新约束）

- 主体改用作者精细网格：Kin Chen 的 CC0 球拍（烘焙握带 / 线床法线）、kyle1003 的 CC BY 4.0 真羽枝羽球、Marin Šarić 的 CC BY 3.0 LibHand（原始皮肤纹理）。模型来源、许可与改动在页面页脚“素材署名”可查。不得暗示手部素材是本人身体照片。
- 保留实际的渐隐玻璃弧、环境反射、宽主光、窄边缘高光与投影。高光超过阈值才产生 bloom，冷白底要透过透明画布，不能把阴影变成白色轮廓。
- 用原作者骨骼摆出斜向松手姿态，缩小掌心、指尖接近球头；原腕部适当延长，保持截面在视口外。托球手部在生活入口从下缘进入，同一滚动进度让手退出、球拍挥动、球头接触线床、羽球掠镜；停滚定格，上滚还原。身体截面不可露出；手、拍和说明文字不能在稳定阅读点相撞。1440 等较窄桌面在开场平移相机留出正文；手机仅在手臂下缘柔和消隐，顶部单独放滚动提示。
- 加载在前一章节预取，模型纹理内嵌，无运行时第三方下载、登录或解码服务。三件源资产未压缩合计约 18 MB，需要持续观察真实网络加载；不能仅凭本机缓存宣称低带宽性能达标。
- 旧 `BadmintonModel.js` 程序主体已移除；球拍 / 球头接触必须以导入网格重新核对。旧版审美 PASS 不沿用。


## 全场秋意与性能（2026-10-25 最新反馈）

- 用户已明确认可精细羽毛球章节，继续改动时保留其模型、摄影光影和可逆滚动动作。
- 红枫不只放在庭院内：枝条延伸到全画面的边缘，产生探出墙外、近处枝叶与远处古厝的层次。用户最新明确要求停滚后仍有风吹、翻转和落叶；环境风独立持续，镜头与接近羽毛球时的收回仍跟随滚动。成果章保持边缘枝叶，不得遮挡正文。
- 落叶必须是有闭合薄边、卷曲和叶脉起伏的三维体，翻转时可见正背面与侧向受光。拒绝平面五角星、alpha卡片或只有弯曲表面的纸片；优先参考有明确许可的真实叶片素材。近处落叶要有足够尺寸，让体积和翻转可被看见。
- 手机探枝须单独缩小并放到上缘，保全姓名和 OPD + RL 的关键笔画。落叶进入阅读区域前柔和淡出，湿石倒影不延伸到研究标题后面；不要仅通过提高文字层级来掩盖遮挡。
- 雨后石面的局部倒影服务于氛围与空间，不做全屏模糊或无边界镜面。使用有限分辨率反射，与落叶一起在不可见时暂停。
- 滚动流畅度与资源预算是验收的一部分：不在转场中反复调整 canvas 缓冲，不重绘 opacity=0 场景；帧请求合并、静态阴影缓存、实例化叶片、离屏缩小目标。停滚后的风只更新前景，主建筑与倒影复用缓存；离屏与减少动态效果仍完全停算。内存配置估算、JS heap 和真实 GPU/帧率数据必须区分。
- 实现和可复现指标见 [courtyard-atmosphere-performance.md](./courtyard-atmosphere-performance.md)。
