# 滚动性能交付记录 · 2026-10-27

## 实现

生产入口从 Remotion Player 改为 GSAP 3.15.0 / ScrollTrigger。一个连续进度通道供 DOM 和 Three.js 直接订阅，保留镜头、挥拍、进入与退出的原有纯函数。React 不再随每个滚动采样重建整套画面；进度条改用 transform。

字形轮廓移入 Worker，最多缓存 32 个模板；再访问章节直接复用几何。字体加载版本纳入缓存 key，页面退出终止 Worker 并释放材质和纹理。Worker 不可用时逐字分批回退，个人资料仍可访问。

相邻章节停画但保留有上限的 framebuffer，离屏或后台才缩小，避免逆向进入时重复分配。庭院 2 MP、体育 2.8 MP 上限；庭院动态绘制上限 60 Hz，环境风约 30 Hz。调度保留时间余数，避免 75 / 90 / 144 Hz 显示器被错误降到半速。模型网格、文字尺寸与体育灯光不变。

体育素材在首个静止阅读段预取；全部素材、灯光与环境就绪后使用 Three.js `compileAsync`，并预热一帧。原始 GLB 合计仍约 18 MB，不将本机读取速度当作弱网证据。

依据与许可证见 [第一方实现调研](./open-source-motion-performance.md)。GSAP 为 Standard No Charge 许可；Three.js 与 cannon-es 为 MIT。没有重新抄写滚动平滑框架，也没有引入第二套 Lenis 平滑循环。

## 测量口径

- Apple M4、16 GB RAM；Google Chrome 156.0.8078.48。
- 相同 Chrome 标签页，交替访问旧生产构建与最终构建；固定同一 CSS 尺寸和 DPR。19 秒轨迹：1 秒准备、12 秒正向、6 秒反向。结果只统计后 18 秒。
- rAF 间隔是浏览器主线程节拍，不能当作真实 GPU 呈现 FPS。长任务来自 PerformanceObserver；超过 50 ms 的 rAF 间隔单独统计。
- 预览构建复制到 `outputs/performance/` 后才注入本地测量按钮。发布目录没有测量 UI、自动滚动代码或遥测。
- 早期窗口曾从 2048×984 切到 1470×775，刷新节拍也变化；不同视口/刷新率记录不做收益对照。正式对照使用同一标签页的 release JSON。

CSS 1470×775、DPR 2，当前显示节拍约 60 Hz。这里的“首次”指本次页面加载后的首次完整故事遍历，不是网络冷缓存；新版本已在首个阅读段预热体育。正式原始结果见 [motion-performance-data.json](./motion-performance-data.json)。

这是 2026-10-28 在全部视觉修复完成后的复测。四组记录的 `valid` 与 `authoredTransforms` 均为 true；一组被窗口状态变化打断的旧版暖缓存记录作废并重测。

主要收益是减少长停顿，不能据平均值宣称所有画面恒定 60 FPS。暖缓存 P95 为 18.7 → 18.3 ms；新版本仍有少量超过 25 ms 的间隔。体育两轮均无 >50 ms 间隔。CPU 任务统计与视觉复验共同作为本机交付证据，弱 GPU、真实手机触摸与弱网不在本轮测量范围。
